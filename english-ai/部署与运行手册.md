# 英语陪练 H5 · 部署与运行操作手册

> 项目目录：`f:\trae-workspace\english-ai`
> 技术栈：Vue3 + Vite + Tailwind CSS 4 + Node 原生 HTTP 服务
> 最后更新：2026-11-13

---

## 一、项目结构

| 路径 | 说明 |
|---|---|
| `src/App.vue` | 主页面：聊天界面、拍照、录音、打卡状态 |
| `src/components/ChatBubble.vue` | 对话气泡组件 |
| `src/utils/api.js` | 前端请求封装，只调用 `/api/*`，不直连第三方 |
| `src/utils/speech.js` | 浏览器语音合成 / 语音识别封装 |
| `src/utils/storage.js` | 本地打卡记录（localStorage） |
| `server/index.js` | Node 服务：托管 `dist` 静态文件 + 提供 `/api/scene`、`/api/chat` |
| `server/config.js` | 只从环境变量读密钥，代码中无任何 Key |
| `.env` | 本地密钥配置（已 git 忽略） |
| `.env.example` | 配置模板 |
| `.env` 中 `PORT` | 后端端口，默认 8787 |

**架构要点**：前端只认 `/api`，密钥只存在于服务端。所以「只有前端、没有 Node 服务」时，拍照识别和 AI 对话一定失败。

## 二、本地运行方案

### 2.1 环境要求

| 项 | 要求 |
|---|---|
| Node.js | ≥ 22.9（`--env-file-if-exists` 需要），推荐 22.x LTS |
| 包管理器 | npm（随 Node 附带） |
| 浏览器 | Chrome / Edge（语音识别依赖），其他浏览器自动降级为文字输入 |

检查版本：

```powershell
node -v
npm -v
```

### 2.2 首次配置

```powershell
cd f:\trae-workspace\english-ai
npm install
```

复制 `.env.example` 为 `.env`（若已存在则跳过），填入密钥：

```ini
BAIDU_API_KEY=百度智能云 API Key
BAIDU_SECRET_KEY=百度智能云 Secret Key
QWEN_API_KEY=阿里云百炼 API Key
QWEN_MODEL=qwen-turbo
PORT=8787
```

密钥申请入口：

| 平台 | 用途 | 地址 |
|---|---|---|
| 百度智能云 → 图像识别 | 场景识别 | https://console.bce.baidu.com/ai/ |
| 阿里云百炼 | 通义千问生成英语 | https://bailian.console.aliyun.com/ |

### 2.3 方式 A：开发模式（改代码即时生效）

需要开两个终端：

```powershell
# 终端 1：后端
cd f:\trae-workspace\english-ai
npm run server
# 输出：server listening on http://0.0.0.0:8787

# 终端 2：前端
cd f:\trae-workspace\english-ai
npm run dev
# 打开 http://localhost:5173
```

Vite 会把 `/api` 代理到 `127.0.0.1:8787`（见 `vite.config.js`），所以前端 5173、后端 8787 各司其职。

### 2.4 方式 B：生产模式（单端口，最接近线上）

```powershell
cd f:\trae-workspace\english-ai
npm run build
npm run server
# 打开 http://localhost:8787
```

此模式下 `dist` 页面和 `/api` 由同一个 Node 进程提供，不依赖 Vite。

### 2.5 手机访问（同一 WiFi）

1. 启动「方式 A」或「方式 B」
2. 查本机局域网 IP：

```powershell
ipconfig | Select-String "IPv4"
```

3. 手机浏览器打开：
   - 方式 A：`http://<你的IP>:5173`
   - 方式 B：`http://<你的IP>:8787`

注意事项：

| 问题 | 说明 |
|---|---|
| 打不开 | Windows 防火墙需放行 Node；首次运行时会弹窗，选「允许」 |
| 摄像头 | 手机端用 `<input capture>` 调系统相机，不要求 HTTPS，可正常拍照 |
| 语音识别 | 必须 Chrome/Edge；部分手机浏览器不支持，页面会自动显示文字输入框 |
| 语音朗读 | 依赖系统 TTS，iOS 需先让用户点一次屏幕才允许播放 |

### 2.6 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 启动前端开发服务器（5173） |
| `npm run server` | 启动 Node 服务（8787） |
| `npm run build` | 构建到 `dist` |
| `npm run preview` | Vite 预览构建产物（不含 `/api`，仅供看样式） |

## 三、线上部署方案

### 3.1 线上现状

| 项 | 值 |
|---|---|
| 托管平台 | Trae 部署（`*.traesite.cn`） |
| 站点名称 | 英语陪练H5 |
| Site ID | `37jgya34t6sjd7r64z5` |
| 访问地址 | https://37jgya34t6sjd7r64z5.traesite.cn |
| 可见性 | 私有（仅本人账号可访问） |
| 当前类型 | StaticWeb（纯静态，**无后端**） |

> 目前的线上版本是早期的纯静态站，页面能开但拍照/对话不可用。需要按 3.3 升级为 Node 服务。

### 3.2 部署包

已整理在 `f:\trae-workspace\english-ai-deploy`：

| 文件 | 作用 |
|---|---|
| `src/` `server/` `public/` `index.html` `vite.config.js` | 应用源码 |
| `package.json` `package-lock.json` | 依赖清单（走 npmmirror 国内镜像） |
| `build.sh` | 远端构建：`npm ci` → `npm run build` → 拷 `server/`、`run.sh` 进 `dist/` |
| `run.sh` | 启动 `node server/index.js` |
| `execution-config.example.json` | 运行配置模板（密钥填这里） |

运行时说明：

- 运行环境 `nodejs20`
- 启动脚本 `run.sh`，输出目录 `dist`
- 服务端读 `process.env.PORT`，因此 `runtime.port` 与 `PORT` 必须同为 `8000`
- `server/index.js` 只用 Node 内置模块，运行时不需要 `node_modules`，包体很小

### 3.3 首次部署（静态站升级为 Node 服务）

**第 1 步：生成密钥配置**

复制 `execution-config.example.json` 为 `execution-config.json`，填入真实密钥：

```json
{
  "schema_version": 1,
  "build": {
    "runtime_key": "nodejs20",
    "build_script": "build.sh",
    "output_dir": "dist",
    "environment": {},
    "timeout_seconds": 3600
  },
  "runtime": {
    "runtime_key": "nodejs20",
    "start_script": "run.sh",
    "port": 8000,
    "environment": {
      "BAIDU_API_KEY": "你的百度AK",
      "BAIDU_SECRET_KEY": "你的百度SK",
      "QWEN_API_KEY": "你的通义千问Key",
      "QWEN_MODEL": "qwen-turbo",
      "PORT": "8000"
    }
  }
}
```

**第 2 步：执行部署**

```powershell
$cli = "C:\Users\Administrator\.trae-cn\plugins\trae-remote-official\deployment\0.0.40\skills\deployment\bin\win32-x64\trae-deploy.exe"

# 检查是否有正在进行的部署
& $cli deployments list --site-id 37jgya34t6sjd7r64z5

# 创建部署，记录返回的 deployment_id
& $cli deployments create `
  --site-id 37jgya34t6sjd7r64z5 `
  --title "英语陪练 H5 v2 Node服务" `
  --description "静态站升级为 Node 服务，同源托管前端页面与 /api 场景识别、AI 对话接口" `
  --type function-web `
  --source-dir "f:\trae-workspace\english-ai-deploy" `
  --execution-config "f:\trae-workspace\english-ai-deploy\execution-config.json" `
  --app-tags 101,301

# 等待终态（默认最长 60 秒一轮）
& $cli deployments wait --deployment-id <上一步返回的 deployment_id>
```

**第 3 步：验证**

```powershell
& $cli deployments get --deployment-id <deployment_id>
& $cli sites get --site-id 37jgya34t6sjd7r64z5
```

浏览器打开 https://37jgya34t6sjd7r64z5.traesite.cn ，拍照后应能返回场景标签和三句英语。

### 3.4 后续更新版本

代码改动后，同步到部署包目录，再执行一次第 2 步即可（站点不需要重建）：

```powershell
$proj = "f:\trae-workspace\english-ai"
$dst  = "f:\trae-workspace\english-ai-deploy"
Copy-Item "$proj\src" -Destination $dst -Recurse -Force
Copy-Item "$proj\server" -Destination $dst -Recurse -Force
Copy-Item "$proj\index.html","$proj\package.json","$proj\package-lock.json","$proj\vite.config.js" -Destination $dst -Force
```

### 3.5 常见部署问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 报类型不匹配 | 旧站是 StaticWeb，不允许直接改类型 | 新建站点：`sites create --name "英语陪练H5-Node" --description "..."`，用新 Site ID 重新部署 |
| `BUILD_SCRIPT_FAILED` 且提示缺少 `@tailwindcss/oxide-linux-x64-gnu` / `rollup` 平台包 | lock 文件在 Windows 生成，缺 Linux 原生依赖记录 | 在项目里重新生成 lock（`npm install --package-lock-only`），重新准备部署包再部署 |
| 构建拉包超时 | 远端访问 npm 慢 | 确认 `build.sh` 使用 `registry.npmmirror.com` |
| 部署成功但页面 404 | `output_dir` 或 `start_script` 配错 | 确认 `output_dir=dist`、`start_script=run.sh`，且 `build.sh` 把 `server/`、`run.sh` 拷进了 `dist/` |
| 页面能开但接口 500 | 运行时环境变量缺失 | 检查 `execution-config.json` 的 `runtime.environment` 三个 Key 是否齐全 |
| 本地起的服务异常退出 | 缺环境变量 | 终端会打印 `[startup] 缺少环境变量: ...`，补 `.env` 即可 |

查看日志：

```powershell
& $cli logs build   --deployment-id <deployment_id>
& $cli logs deploy  --deployment-id <deployment_id>
& $cli logs runtime --deployment-id <deployment_id>
```

## 四、安全约定

1. 密钥只放两处：本地 `.env`、线上 `execution-config.json` 的 `runtime.environment`。**不要写进 `src/` 或 `server/` 源码**。
2. `.env` 已被 `.gitignore` 忽略；`execution-config.json` 位于部署包目录，**不要提交到任何仓库**。
3. 建议定期重置密钥。本地服务一旦把 Key 打印到日志、截图或对话中，等同于泄露。
4. 线上站点默认私有（仅本人可访问）。如需他人访问，需显式改为 public：`sites update-config --site-id ... `（在平台侧确认后再执行）。

## 五、方案选型建议

| 场景 | 推荐方案 |
|---|---|
| 日常自己练 | 本地方式 B（`npm run build` + `npm run server`），单端口、无跨域、最稳 |
| 边改边调 UI | 本地方式 A（双终端） |
| 通勤时手机随时用 | 线上 Node 服务版；注意语音识别在移动端浏览器支持有限，可退回文字输入 |
| 只想给别人看界面 | 现有静态站即可，不必升级 |
